# 20 · Vector autoregressions

**45 minutes** · after *19 · Sequential models* · next: *21 · Parameter
variants*

Every model in this series so far was written down and then calibrated or
estimated one parameter at a time. A vector autoregression is the opposite
arrangement. Its form is fixed — each variable is a linear function of the
recent history of all of them — and the coefficients come entirely from the
data in a single least-squares step.

That makes it the standard benchmark. It imposes almost no economics, so
whatever a structural model achieves beyond a VAR is attributable to the
structure rather than to the data.

```{code-cell} ipython3
import numpy as np
import plotly.graph_objects as go
from plotly.subplots import make_subplots
from irispie import (Simultaneous, RedVAR, Databox, Series, qq,
                     MinnesotaPriorObs, MeanPriorObs)

CORE_SOURCE = """

!transition-variables
    y, pi, i, q, y_w, pi_w, i_w

!transition-shocks
    shk_y, shk_pi, shk_i, shk_q, shk_y_w, shk_pi_w, shk_i_w

!parameters
    a1, a2, a3, a4, b1, b2, b3, c1, c2, c3
    pi_tar, r_ss, beta, psi
    d1, d2, d3, pi_w_ss, r_w_ss

!transition-equations
    y = a1*y{-1} - a2*(i - pi{+1} - r_ss) + a3*q + a4*y_w + shk_y;

    pi - pi_tar = b1*(pi{-1} - pi_tar) + beta*(1-b1)*(pi{+1} - pi_tar)
                + b2*y + b3*q + shk_pi;

    i = c1*i{-1} + (1-c1)*(pi_tar + r_ss + c2*(pi - pi_tar) + c3*y) + shk_i;

    q = q{+1} - ((i - pi{+1}) - (i_w - pi_w{+1}))/4 - psi*q + shk_q;

    y_w = d1*y_w{-1} + shk_y_w;
    pi_w = d2*pi_w{-1} + (1-d2)*pi_w_ss + shk_pi_w;
    i_w = d3*i_w{-1} + (1-d3)*(pi_w_ss + r_w_ss) + shk_i_w;

"""

CALIB = dict(a1=0.7, a2=0.2, a3=0.1, a4=0.3, b1=0.1, b2=0.3, b3=0.2,
             c1=0.5, c2=1.5, c3=0.5, pi_tar=2, r_ss=1, beta=0.99, psi=0.1,
             d1=0.8, d2=0.7, d3=0.8, pi_w_ss=2, r_w_ss=1)

STDS = dict(std_shk_y=0.4, std_shk_pi=0.3, std_shk_i=0.2, std_shk_q=0.5,
            std_shk_y_w=0.3, std_shk_pi_w=0.2, std_shk_i_w=0.2)

core = Simultaneous.from_string(CORE_SOURCE, linear=True, flat=True)
core.assign_strict(**CALIB)
core.assign(**STDS)
core.steady()
core.solve_first_order()

LONG = qq(1990,1) >> qq(2024,4)

rng = np.random.default_rng(5)
shocks_in = Databox.steady(core, LONG)
for name in ("shk_y", "shk_pi", "shk_i", "shk_q",
             "shk_y_w", "shk_pi_w", "shk_i_w"):
    shocks_in[name] = Series(start=LONG[0],
                             values=rng.normal(0, STDS["std_" + name], len(LONG)))

history = core.simulate(shocks_in, LONG)

data = Databox()
for name in ("y", "pi", "i"):
    data[name] = history[name]

print("history:", len(LONG), "quarters of", sorted(data.get_names()))
```

The data is thirty-five years generated by the structural model. Three of
its seven variables are kept, which is the usual situation: a VAR is
estimated on the series that are published, and the rest of the economy acts
on them without being observed.

## Specifying and estimating

A `RedVAR` is defined by its variables, its order and whether it has an
intercept. Nothing else is specified, because nothing else is a choice.

```{code-cell} ipython3
var = RedVAR(endogenous_names=["y", "pi", "i"], order=2)

fitted = var.estimate(data, LONG)

print("order        :", var.order)
print("intercept    :", var.has_intercept)
print("variables    :", list(var.get_endogenous_names()))
print()
print("estimate returned:", sorted(fitted.get_names()))
```

`estimate` returns a databox rather than modifying one. It contains the
input series, the fitted values under `cnd_`, and the residuals under
`res_`. The coefficients are stored on the model object.

## The coefficients

```{code-cell} ipython3
system = var.get_system_matrices()

print("A, coefficients on lagged variables, shape", np.asarray(system.A).shape)
print(np.round(np.asarray(system.A), 4))
print()
print("c, intercepts:", np.round(np.asarray(system.c), 4))
print()
print("residual covariance:")
print(np.round(np.asarray(system.cov_residuals), 4))
```

`A` has one row per equation and one column per right-hand side term: three
variables at two lags gives six columns, with the first lag in the first
three. Reading the first row, output depends on its own first lag with a
coefficient of `0.6352` and on lagged inflation with `0.2752`.

Those numbers do not correspond to anything in the structural model, and
should not be expected to. The structural equations contain expectations of
the future and four variables the VAR never sees; what the VAR estimates is
the reduced form those equations imply for these three series, which is a
different object.

The residual covariance is not diagonal. The off-diagonal entries are
substantial — `0.1117` between inflation and the interest rate against
variances of `0.1484` and `0.1225`. A reduced-form residual is a mixture of
the structural shocks, so the three move together, and separating them again
is the identification problem that structural VAR analysis exists to solve.

## Companion form and stability

A VAR of order two is a first-order system in a stacked vector. That
rearrangement is the companion form, and IrisPie returns it as the same
`Solution` object tutorial 8 produced for the structural model:

```{code-cell} ipython3
companion = var.get_companion_matrices()
T = np.asarray(companion.T)

print("T shape:", T.shape)
print()
print("top block, the coefficients:")
print(np.round(T[:3, :], 4))
print()
print("bottom block, the shift:")
print(np.round(T[3:, :], 4))
```

The top three rows are `A`. The bottom three move last quarter's values into
the lagged positions, which is bookkeeping rather than economics. Stacking
in this way means the whole apparatus of tutorial 8 applies: the dynamics of
the VAR are the eigenvalues of `T`.

```{code-cell} ipython3
eigenvalues = np.asarray(var.get_eigenvalues()).ravel()

print("eigenvalues:")
for value in eigenvalues:
    print(f"  {value.real:+.4f} {value.imag:+.4f}j   modulus {abs(value):.4f}")
print()
print("largest modulus:", round(var.get_max_abs_eigenvalue(), 4))
print("stable         :", var.get_stability())
print()
print("same as the eigenvalues of T:",
      np.allclose(np.sort_complex(np.linalg.eigvals(T)),
                  np.sort_complex(eigenvalues)))
```

Six eigenvalues for three variables at two lags. The largest has modulus
`0.7971`, comfortably inside the unit circle, so the estimated system is
stationary and `get_stability` reports `True`. The complex pairs produce
cycles rather than smooth decay.

Stability is not guaranteed by estimation. Least squares fits the sample,
and a sample can be fitted by an explosive system, particularly when the
order is high relative to the number of observations. The exercise at the
end of this tutorial produces exactly that.

## Priors

Least squares has no opinion about what the coefficients should be, which is
a problem when the sample is short. IrisPie supplies prior information as
dummy observations appended to the regression, which is the standard device.

```{code-cell} ipython3
SHORT = qq(2015,1) >> qq(2024,4)       # forty quarters

def summarise(label, prior):
    model = RedVAR(endogenous_names=["y", "pi", "i"], order=2)
    model.estimate(data, SHORT, prior_obs=prior)
    coefficients = np.asarray(model.get_system_matrices().A)
    print(f"  {label:26} largest modulus {model.get_max_abs_eigenvalue():.4f}"
          f"   sum of |A| {np.abs(coefficients).sum():6.3f}")

summarise("no prior", None)
summarise("Minnesota, rho=0.9", MinnesotaPriorObs(rho=0.9, mu=1.0))
summarise("Minnesota, rho=0, mu=5", MinnesotaPriorObs(rho=0.0, mu=5.0))
summarise("mean prior", MeanPriorObs(mean=np.array([0.0, 2.0, 3.0]), mu=1.0))
```

`MinnesotaPriorObs` shrinks the coefficients towards a stated persistence.
`rho` is the first-lag coefficient the prior believes in and `mu` is how
strongly it is believed: `rho=0.9` pulls the system towards independent
near-random-walks, and `rho=0` with a large `mu` pulls it towards white
noise, which here cuts the sum of absolute coefficients from `5.940` to
`0.797`.

`MeanPriorObs` is a different statement. It constrains the implied
unconditional means rather than the dynamics, which is why the figures above
barely move: it was given means close to those the data already implies.

Priors are not a formality on short samples. Forty quarters and seven
coefficients per equation is the territory where least squares begins to fit
noise, and a prior is the standard way to keep an estimate sensible when the
sample alone cannot determine it.

## Choosing the order

The order is the one specification choice a VAR leaves open, and the two
obvious ways to make it disagree. Estimating every order from one to eight
on the forty quarters of `SHORT`:

```{code-cell} ipython3
ORDERS = range(1, 9)

fit = []
stability = []

print(f"{'order':>6} {'coefficients':>13} {'observations':>13}"
      f" {'largest modulus':>16} {'residual sd':>12}")
for order in ORDERS:
    trial = RedVAR(endogenous_names=["y", "pi", "i"], order=order)
    trial.estimate(data, SHORT)
    coefficients = np.asarray(trial.get_system_matrices().A).shape[1] + 1
    residual_sd = float(np.sqrt(np.asarray(trial.get_cov_residuals())[0, 0]))
    modulus = trial.get_max_abs_eigenvalue()
    fit.append(residual_sd)
    stability.append(modulus)
    print(f"{order:6} {coefficients:13} {len(SHORT)-order:13}"
          f" {modulus:16.4f} {residual_sd:12.4f}")
```

The residual standard deviation falls at every step, from `0.2969` to
`0.1959`. That is not evidence of a better model. Each additional lag adds
three coefficients per equation, and additional coefficients always improve
the fit of a sample; at order eight there are twenty-five of them per
equation and thirty-two observations to determine them.

The largest eigenvalue modulus moves the other way, and crosses one between
orders five and six. Beyond that the estimated system is explosive: simulate
it forward and it diverges, although the data it was fitted to is stationary
by construction.

```{code-cell} ipython3
figure = make_subplots(
    rows=2, cols=1, shared_xaxes=True, vertical_spacing=0.08,
    subplot_titles=("Residual standard deviation of output",
                    "Largest eigenvalue modulus"),
)

figure.add_trace(go.Scatter(x=list(ORDERS), y=fit, mode="lines+markers",
                            line=dict(width=3), marker=dict(size=9),
                            showlegend=False), row=1, col=1)
figure.add_trace(go.Scatter(x=list(ORDERS), y=stability, mode="lines+markers",
                            line=dict(width=3, color="rgb(230,80,60)"),
                            marker=dict(size=9), showlegend=False), row=2, col=1)

figure.add_hline(y=1.0, line_width=2, line_dash="dot", line_color="black",
                 row=2, col=1)
figure.update_layout(
    title="Adding lags improves the fit and destroys the stability",
    height=620, template="plotly_white",
)
figure.update_xaxes(title_text="order", dtick=1, row=2, col=1)

figure
```

The two panels are the whole difficulty of order selection. Judged on the
upper panel alone the answer is eight; judged on the lower panel it is five
at most. The dotted line is the boundary between a model that can be
forecast with and one that cannot, and the fit gives no sign of it being
crossed.

Neither panel is the criterion a practitioner would use, which is an
information criterion penalising the coefficient count, or out-of-sample
performance. Both of those are arithmetic the user supplies; IrisPie reports
the pieces. What the lower panel adds is a constraint rather than a
criterion: an order whose estimate is explosive is not a candidate however
well it fits.

## Resampling

`resample` repeats the simulation with the residuals disturbed, which
produces alternative histories consistent with the estimated coefficients.
It takes three methods, and only one of them is implemented:

```{code-cell} ipython3
import ast, inspect
import irispie.red_vars._simulators as simulators

for method in ("monte_carlo", "bootstrap", "wild_bootstrap"):
    function = getattr(simulators, f"_resample_residuals_by_{method}")
    body = ast.parse(inspect.getsource(function)).body[0].body
    executable = [node for node in body
                  if not (isinstance(node, ast.Expr)
                          and isinstance(node.value, ast.Constant))]
    print(f"  {method:15} executable statements in the implementation: "
          f"{len(executable)}")
```

`monte_carlo` and `bootstrap` contain no statements at all. They are
accepted, they run, and they return the requested number of variants with
the residuals untouched, so every variant is identical. Nothing reports a
problem. Use `wild_bootstrap`, which multiplies each residual by a random
factor:

```{code-cell} ipython3
REPLAY = qq(1991,1) >> qq(2024,4)      # clear of the initial lags

resampler = RedVAR(endogenous_names=["y", "pi", "i"], order=2)
refitted = resampler.estimate(data, LONG)
resampler.expand_num_variants(200)

inputs = Databox()
for name in ("y", "pi", "i", "res_y", "res_pi", "res_i"):
    inputs[name] = refitted[name]

replayed = resampler.resample(inputs, REPLAY, method="wild_bootstrap")
paths = np.asarray(replayed["y"][REPLAY])

print("alternative histories :", paths.shape[1])
print("all finite            :", bool(np.isfinite(paths).all()))
print("spread across them    :", round(float(paths.std()), 3))
print("spread of the actual  :",
      round(float(np.nanstd(np.asarray(data["y"][REPLAY]))), 3))
```

Two requirements are not obvious. The model's variants must be expanded
first, as in tutorial 18, and the input databox must contain the residuals,
because a wild bootstrap rescales residuals that already exist rather than
drawing new ones. The span must also start clear of the first `order`
periods, where the residuals are `nan` and would propagate.

Two hundred alternative histories have a spread close to that of the history
that actually occurred, which is the expected result: these are the same
shocks with their signs and sizes disturbed.

The exact figure changes between runs. The random factors are drawn from a
generator created when the module is imported, and `resample` takes no seed
argument, so a wild bootstrap cannot be reproduced exactly. Where a
reproducible fan is required, the residuals have to be disturbed explicitly
and passed in, as in tutorial 18.

## ⚠️ Break it

**Resampling with a method that does nothing.**

```{code-cell} ipython3
quiet = resampler.resample(inputs, REPLAY, method="monte_carlo")
quiet_paths = np.asarray(quiet["y"][REPLAY])

print("variants returned      :", quiet_paths.shape[1])
print(f"largest spread         : {quiet_paths.std(axis=1).max():.3e}")
print("first and last identical:",
      bool(np.array_equal(quiet_paths[:, 0], quiet_paths[:, -1])))
```

Two hundred variants, every one of them the same series: the first and the
last are equal to the last bit, and the largest spread across variants is
`3.331e-16`, which is floating-point noise rather than variation. The call
accepted the method name, the output has the shape a fan chart needs, and
`num_variants` reports two hundred.

Every downstream step then works. `ip.percentile` over identical variants
returns that series for every percentile, so the fan chart draws with all
bands lying on the median. The output is a forecast presented with no
uncertainty at all, produced by a method whose purpose is to quantify
uncertainty.

The check is the one from tutorial 18, applied to the variants rather than
their count. Note the tolerance: a test against zero would pass on the
`3.331e-16` above, so the comparison has to be against something larger than
machine noise.

```{code-cell} ipython3
def has_real_variation(paths, tolerance=1e-8):
    """True when the variants differ by more than floating-point noise."""
    return bool(paths.std(axis=1).max() > tolerance)


print("wild bootstrap :", has_real_variation(paths))
print("monte carlo    :", has_real_variation(quiet_paths))
```

A count of variants says nothing, and neither does a spread greater than
zero. Measure the spread against a tolerance.


## Things to remember

1. **A VAR is specified by its variables, order and intercept**, and
   everything else comes from the data.
2. **`estimate` returns a databox** of fitted values and residuals; the
   coefficients are stored on the model.
3. **The residual covariance is not diagonal.** Reduced-form residuals mix
   the structural shocks.
4. **The companion matrix is a `Solution`**, the same object the structural
   models produce, so stability is read from its eigenvalues.
5. **Estimation does not guarantee stability.** Check
   `get_max_abs_eigenvalue` rather than assuming it.
6. **Priors are dummy observations.** `MinnesotaPriorObs` shrinks the
   dynamics towards a stated persistence; `MeanPriorObs` constrains the
   implied means.
7. **Only `wild_bootstrap` is implemented.** `monte_carlo` and `bootstrap`
   return identical variants without warning.
8. **Resampling needs expanded model variants, residuals in the input, and
   a span clear of the initial lags.**

coefficients should look like, and it pulls in whichever direction that
statement requires.

the two and the prior pulls down, which buys two more orders before the
system becomes explosive.

It does not rescue order eight, which still comes back at `1.0122`. A prior
supplies information the sample lacks; it cannot supply enough to determine
twenty-five coefficients per equation from thirty-two observations. The
remedy for too many coefficients is fewer coefficients.
